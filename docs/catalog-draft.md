## p.2 — 제품 개요 (Why SLM)

### 상수도 운영의 3가지 현실

1. **데이터는 많지만 판단은 어렵다** — SCADA 태그 수천 개, 알람 수백 건.
   무엇이 진짜 이상인지 걸러주는 체계가 없다.
2. **현장과 관제가 분리되어 있다** — 알람은 관제실에, 조치 기록은 수첩에.
   오탐/미검지 분석이 불가능하다.
3. **폐쇄망이라 최신 AI를 못 쓴다** — 클라우드 LLM 기반 솔루션은
   상수도 보안 환경에 반입 자체가 불가하다.

### SLM의 답

**SLM은 상수도 자산의 전 수명주기(Lifecycle)를 하나의 시스템으로 관리합니다.**

| 축 | 제공 가치 |
|----|-----------|
| **감시** | 실시간 계통도 · GIS 관망도 · 트렌드로 설비 상태 완전 가시화 |
| **알람** | 분류별 경보 + 오탐·미검지 분석 + 현장 조치 통합 |
| **장비 고장 관리** | AI 채팅 진단 + 고장 케이스 DB + 조치 이력 · 교체 후보 |
| **관망 구축·조회** | 시설·설비·태그·매뉴얼·GIS를 일관된 모델로 구성 |

> **핵심 한 줄**: 모든 AI가 **로컬에서 구동**됩니다. 외부 인터넷·클라우드
> 의존이 0인, 폐쇄망 완결형 솔루션입니다.

## p.4–5 — 차별화 포인트 (펼침면)

### ① AI 멀티모달 현장 진단 — 폐쇄망에서 동작하는 유일한 접근

현장에서 찍은 설비 사진 한 장으로:
- **장비 자동 식별** (PLC/인버터/RTU/모뎀/UPS 등 명판 파싱)
- **매뉴얼 RAG** — 해당 장비 매뉴얼 PDF에서 관련 절 자동 인용
- **고장 케이스 DB** — 유사 고장 사례·조치 이력 자동 매칭

모든 추론은 **로컬 GPU + Ollama**에서 수행. 사진이 외부로 나가지 않습니다.

`[화면]` 채팅 사진 업로드 → 진단 카드 캡처

### ② 알람 ↔ 현장 조치 통합 분석

자동 알람의 오탐·미검지를 실제 현장 조치 이력과 대조하여
**설비 교체 후보를 자동 식별**합니다.
- 내용연수 · MTBF · 재발 지속 **3신호 융합** 교체 우선순위 Top 5
- 설비 건강성 대시보드 (`/monitoring/equipment-health`)

### ③ 자연어 장애·조치 기록

현장 작업자가 **대화하듯** 기록합니다.
> "동문 가압장 2번 펌프 인버터에서 소음 발생, 사진 첨부"

시설·설비·태그가 **자동 매칭**되고, 조치 완료까지 채팅으로 마감.
모바일 **현장 모드**(`/field`)로 이동 중에도 알람 대응·일상 점검이 가능합니다.

### ④ Zero-Hallucination 원칙

AI 참고 의견은 DB 사실과 **시각적·구조적으로 분리**됩니다.
- 별도 카드 + `[AI 참고 의견]` 접두어
- 수치 생성 차단 — 숫자는 DB 조회값만 표시

**운영 판단의 근거가 되는 값은 항상 실측 데이터입니다.**

`[화면]` AI 참고 의견 분리 카드 캡처

## p.6 — 감시: 실시간 모니터링

### 종합 현황판
- KPI 6종 (이상 감지 · 교차검증 · 설비 장애 · 유량 불균형 · 진행중 경보 · 정상 시설)
- 이상 시설 TOP · 유량 불균형 TOP · 시설유형별 이상 분포
- 카드 클릭 → AI 진단 즉시 실행 (SSE 스트리밍)

### 시설 모니터링
- 배수지 · 가압장 · 블록 · 감압시설 전용 화면
- 모니터링 카탈로그 기반 구성 — 사이트별 태그 구성 자유 정의
- 알람 한계선(HH/LL) 표시, 30초 자동 갱신

### 트렌드 분석
- 다중 태그 비교, 기간 자유 선택, 통계 카드 (Min/Max/Avg/Last)
- **평소 대비** — 머신러닝(GBT) 기반 정상 기대값 대비 편차 판정
- **향후 전망** — 시계열 파운데이션 모델(Chronos) 단기 예측 밴드

### 실시간 계통도 (용수 흐름)
- 유량 비례 엣지 굵기 · 상태 색상 · 타임라인 재생(24h 되감기)
- 노드 클릭 → 트렌드/시설/알람/AI 진단 팝업

`[화면]` 대시보드 + 계통도 캡처 2점

## p.7 — 감시: GIS 관망도

- **오프라인 지도 내장** — 외부 지도 CDN 의존 없음 (폐쇄망 기본)
- 줌 레벨 자동 LOD — 마커 → 축약 카드 → 확장 카드(Q/H/P + 기능 버튼)
- 시설유형별 색상 체계 (배수지·가압장·감압·블록)
- 알람 상태 실시간 반영 (경고=빨강 / 주의=주황)
- SHP 레이어 — 관로 · 밸브 · 블록경계 표시
- 타임라인 스크러버 — 24시간 되감기 · 재생 · 알람 도트
- EPANET 시뮬 오버레이 — 압력 히트맵 · 유량 방향 (옵션 모듈)

`[화면]` GIS 관망도 전체 + 확장 카드 캡처

## p.8 — 알람: 경보 관리 체계

### 경보 현황·이력·분석
- 실시간 경보 대시보드 (요약 카드 · 카테고리 도넛 · 시설별 집계)
- 카테고리 9종 (수위/압력/유량/밸브/펌프/통신/네트워크/UPS/수질)
- 경보 분석 — 진단원인 · 대응방안 · 필터결과 · 운영현황 구조화 표출

### 지능형 이상 감지
- **시설 단위 다변량 Isolation Forest** — 누수 의심 · 펌프 공회전 ·
  하류 차단 등 단일 센서로는 못 잡는 복합 이상 탐지
- **센서 품질 감지** — 포화 · 고착 · DI 반전 등 센서 자체 이상 분리
- **야간최소유량 CUSUM 누수 감지** — 누수 의심 자동 알림 + 선정 사유 서술
- 교차검증(edge mismatch) · 물수지 불균형 검증

### 알람 → 작업 연동
- 알람 확인 → **작업 등록 원클릭** (시설·유형·카테고리 자동 채움)
- 예방정비 기간 중 해당 알람 억제 (원인 추적 가능한 구조)
- 알람 발생 시 위기대응 모달 (경고 모달 / 주의 toast — 사이트 설정 토글)

`[화면]` 경보 분석 2패널 + 위기대응 모달 캡처

## p.9 — 장비 고장 관리

### 장애 이력 관리
- 장애 분류 4종 정책 (고장/이상/교체/점검) — 알람은 "이상",
  현장 확인된 것만 "고장" (오분류 방지 정책 내장)
- 채팅 자연어 등록 + 사진 첨부 + 조치 완료 기록
- 통계 대시보드 — 설비유형별 · 시설별 장애 추이

### 설비 건강성
- 교체 우선순위 Top 5 (내용연수 · MTBF · 재발 3신호 융합)
- 알람 오탐/미검지 ↔ 조치 이력 대조 분석

### 보고서 자동 생성
- **장애 조치 보고서** / **일 점검 보고서** 자동 양식
- 채팅으로 초안 생성 → 검토 → 확정 흐름

### 매뉴얼·고장 케이스 지식베이스
- 장비 매뉴얼 PDF 등록 → 임베딩 기반 검색·인용
- 고장 케이스 DB — 유사 사례 자동 추천

`[화면]` 고장 통계 + 교체 우선순위 카드 캡처

## p.10 — 관망 구축·조회

### 구축 메뉴군 — 시스템을 스스로 구성하는 도구
- 태그 마스터 · 설비 관리 · 배수지/가압장/감압/블록 관리 (CRUD + CSV 일괄)
- 용수 흐름 관리 — 상류→하류 연결 구성
- GIS 설정 — 드래그 좌표 편집 · SHP 레이어
- 인과 규칙 — 시설유형별 인과 체인 · 안전연동 · 역방향 진단 정의
- 캔버스 에디터 — 계통도 직접 작도 + 태그 링크
- 컬럼 잠금 — 현장제어/시스템제어 필드 보호

> **구축 업체 관점**: 초기 구축(태그·시설·계통) 작업을 SLM 안에서
> CSV 일괄 + 화면 CRUD로 수행 — 별도 DB 작업 최소화.

### EPANET 관망수리분석 (옵션 모듈 B1)
- SHP → INP 자동 변환 → 수리 시뮬레이션
- 누수 의심 구간 · 헤드손실 이상 · 차단밸브 영향범위 · 관로 파손 시뮬 ·
  펌프 가동 변경 · 블록 교체 후보 · 관망 노후도 · 수질 체류시간
- 실측 유량 주입 → 시뮬 vs 실측 차이 분석
- 데이터 품질 게이트 — 준비 안 된 메뉴는 요구 데이터 안내

`[화면]` EPANET 시뮬 캔버스 + GIS 오버레이 캡처

## p.14 — 기술 사양·아키텍처

### 시스템 구성

```
[운영자 브라우저] ── HTTPS ── [Next.js 프런트]
                                   │ BFF Proxy
                              [FastAPI 백엔드] ── [PostgreSQL 16 + TimescaleDB]
                                   │
                              [Ollama 로컬 AI] (LLM · Vision · Embedding · STT)
                              [Node-RED] (알람 등급·수집 플로우)
```

| 항목 | 사양 |
|------|------|
| 프런트엔드 | Next.js (App Router) + TypeScript, 다크/라이트 테마 |
| 백엔드 | Python FastAPI |
| DB | PostgreSQL 16 + TimescaleDB (시계열 하이퍼테이블) |
| AI | 로컬 Ollama — LLM · Vision(멀티모달) · 임베딩 · Whisper STT |
| 배포 | Docker Compose, 프로덕션 빌드 + TLS(Caddy) |
| 접속 | 웹 브라우저 (설치 프로그램 불필요), 모바일 반응형 |

### 보안·격리
- **완전 폐쇄망 운영** — 외부 API·CDN·클라우드 LLM·원격 인증 의존 0
- 오프라인 자산 번들 — 지도 타일 · AI 모델 웨이트 · 폰트 일체 반입
- JWT 인증 + bcrypt 비밀번호 + 세션 관리 (잠금·강제 종료)
- **region 기반 멀티테넌시** — 고객·사업소별 데이터 격리
- 권한 3단계 (MASTER/ADMIN/USER) × 메뉴 단위 접근 제어

### 권장 서버 사양 (제안)

| 구성 | 최소 | 권장 (Enterprise) |
|------|------|-------------------|
| CPU | 8 core | 16 core |
| RAM | 32 GB | 64 GB |
| GPU | — (B2 미사용 시) | VRAM 24 GB (B2 Vision) |
| 저장소 | SSD 512 GB | NVMe 2 TB (시계열 보존 기간에 따라) |

## p.15 — 구축·납품 프로세스

1. **요구 분석** — 시설 목록 · 태그 체계 · SCADA 연계 방식 확인
2. **기반 구축** — 태그 마스터 · 시설 · 계통 CSV 일괄 등록 (구축 메뉴 활용)
3. **연계 개발** — SCADA/계측 데이터 수집 연동 (Node-RED 플로우)
4. **모듈 활성화** — SKU 등급에 따라 마스터 토글 설정
5. **오프라인 자산 반입** — 지도·AI 모델 번들 설치 (체크리스트 제공)
6. **검수** — 자동 E2E 스모크 테스트 (대표 인텐트 16종) + 인수 시험
7. **인수인계** — 운영자 가이드 · cron 등록 가이드 · 납품 체크리스트

### 운영·유지보수
- 마이그레이션 기반 무중단 업그레이드 (롤백 절차 포함)
