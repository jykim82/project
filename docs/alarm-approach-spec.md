# 임계 도달 예측 사양 v1

수위의 최근 추세를 선형 외삽해 **임계(HH/LL) 도달 예상 시각을 사전 표출**한다.
현재 경보는 임계를 넘은 뒤에 울린다 — 수위는 물리적으로 느리게 움직여
도달 전에 알 수 있다.

**관련**: `docs/alarm-threshold-coverage.md`(임계 보유 조사),
`docs/trend-comparison-spec.md`(향후 전망 — 목적이 다름, §5)

---

## 1. 대상 — 수위만 (v1)

tagsn 명명 규칙으로 페어링: 같은 설비코드(둘째 세그먼트)의
**`LEI`(수위 측정) ↔ `LEC`(임계 설정, HH/LL 은 datainfo)**.
실측 55개 수위 측정 태그 중 **41개 페어 성립**.

- 압력·유량은 제외 — 압력은 임계 공백 33곳(`alarm-threshold-coverage`)이라
  목표값이 없어 예측 자체가 성립하지 않고, 유량은 임계 감시가 아니라 통계
  감시 소관으로 판정돼 있다.
- 같은 설비에 임계가 복수(지별 설정)면 **먼저 도달하는 임계**를 쓴다 —
  HH 는 현재값보다 큰 것 중 최소, LL 은 작은 것 중 최대. 사전 신호는
  보수적(이른) 쪽이 옳다.

## 2. 계산 — 선형 외삽, 모델 없음

```
기울기  = regr_slope(최근 60분 원시값)      -- 1~3분 간격, 20~60점
도달분  = (임계 - 현재값) / 기울기
```

**Chronos 를 쓰지 않는 것은 의도다.** 단조 추세의 단기 외삽엔 선형이 맞고
(트렌드 "향후 전망"과 목적이 다르다 — §5), 저사양 전제에도 맞다.

게이트 3종 — 셋 다 오탐 억제용:

| 게이트 | 값 | 이유 |
|---|---|---|
| `R² > 0.5` | 회귀 설명력 | 펌프 기동 등으로 출렁이는 태그의 우연한 기울기 차단 |
| `|기울기| > 0.001 m/분` | 시간당 6cm | 이보다 느리면 사실상 정체 |
| `도달 ≤ 240분` (기본) | 4시간 | 수위는 일주기(야간 충수·주간 방류)라 더 먼 외삽은 추세가 그 전에 바뀐다 |

데이터 소스는 **원시 직접 집계**다 (`logtime` 하한 60분 — E-056 원칙).
5분 cagg 는 refresh 지연으로 최근 60분에 2~3버킷뿐이라 회귀가 성립하지
않았다 (실측). 41태그 × 60분 원시는 89ms.

### 2.1 정확도 실측 (백테스트 2026-07-28) — ETA 는 구간으로만 표시

최근 90일 수위 도달 사건으로 백테스트 (도달 시점 t0 기준, t0−LEAD 시점에
운영 로직과 동일한 게이트·회귀로 예측한 ETA 와 실제 LEAD 의 오차):

| 예측 시점 | 사건 수 | 중앙 오차 | p90 오차 |
|---|---:|---:|---:|
| 도달 30분 전 | 16 | ±16.8분 | ±27.9분 |
| 도달 60분 전 | 247 | ±20.0분 | ±55.6분 |

"42분 후" 같은 **분 단위 표시는 거짓 정밀**이다. 화면은 구간
(30분 내 / 1시간 내 / 1~2시간 / 2~4시간)으로만 표시하고, 정확한 분·오차
수준은 툴팁으로 내린다.

### 2.2 왜 그래도 AI(Chronos)가 아닌가

트렌드 "향후 전망"은 Chronos-Bolt 다 (선형 대비 +46.9% 실측 — 형태 예측엔
AI 가 낫다). 그러나 사전 경보는 질문이 다르다: Chronos 는 "가장 그럴듯한
미래"를 답하고, 과거 패턴(야간 충수·펌프 개입)을 학습하므로 "평소처럼
개입이 일어나 임계에 안 닿는다"가 최빈 예측이 된다 — **경보가 필요한 바로
그 상황(개입 실패)을 구조적으로 가린다**. 선형 외삽은 "지금 추세가
유지되면"이라는 조건부 경고라 의미가 맞다. Chronos 병기는 P2 후보지만
가림 위험을 넘어야 한다.

## 3. 예측은 경보가 아니다

**`tb_equipment_alarm_report` 에 아무것도 쓰지 않는다.** 예측 행이 알람
테이블에 들어가면 감사·통계·확인율이 전부 오염된다. 조회 시점 계산(cron
없음) + 화면 표출까지가 v1 의 전부다. UI 툴팁에도 "예측이며 경보가
아닙니다"를 명시한다.

## 4. API·화면

- `GET /alarm/approach?horizon_min=240` (`slm/endpoints/alarm_approach.py`)
  — `monitored_tags`(감시 페어 수)를 함께 반환. **0건이 침묵으로 읽히면 안
  된다** — "41태그 감시 중, 접근 없음"이 정보다.
- 경보관리 **현황 탭** "임계 도달 예측" 섹션 (`AlarmApproachPanel`, 5분
  갱신). 요약 카드 바로 아래 — 사후 경보 목록과 달리 **지금 대응하면
  경보가 되지 않는 것들**이라 위에 둔다. 60분 내 도달은 rose, 그 외 amber.

## 5. 트렌드 "향후 전망"(Chronos)과의 구분

| | 향후 전망 | 임계 도달 예측 (본 사양) |
|---|---|---|
| 목적 | 태그 하나의 시계열 형태 예측 | 임계 대비 남은 시간 |
| 방법 | Chronos-Bolt | 선형 회귀 |
| 소비처 | 트렌드 차트 밴드 | 경보관리 사전 신호 |

합치지 않는다 — 하나로 만들면 "예측"이라는 단어만 같고 판정·비용·화면이
전부 달라 양쪽 다 나빠진다.

## 6. 후속 (P2)

- 알람 벨·위기대응 팝업 합류 (능동 알림) — 표출만으로 부족하다는 운영
  피드백이 있을 때. 자동 경보 생성이 아니라 알림 채널 합류로 한정
- 압력 임계가 보강되면(`alarm-threshold-coverage` SCADA 협의) 압력 확장
