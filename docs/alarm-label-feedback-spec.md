# 경보 판정 라벨(오탐 피드백) 사양 v1 — 로드맵 C P1

이상감지 경보에 운영자가 **실제 / 오탐 / 점검필요**를 1클릭 판정하고,
그 축적으로 **오탐률 추이**를 만든다. "도입 후 오탐률 42% → 11%" 형태의
정량 실적이 목표다 (`slm-feature-roadmap-draft.md` §3.C).

**관련**: 로드맵 부록 A.4(기반 현황)·B.4(초기 정책),
`docs/alarm-chattering-spec.md`(라벨링 우선 대상),
`docs/chat-feedback-telemetry-spec.md`(**다른 체계** — §5)

---

## 1. 왜 3분법인가 — 기존 2분법의 한계

기존 `is_false_alarm` 은 'Y'/'N' 인데 **'N' 이 기본값**이라
"실제 이상으로 확인됨"과 "아직 판정 안 함"을 구분하지 못한다.
오탐률 = 오탐 / **판정된 것** 인데 분모가 서지 않는다.

| 라벨 | 의미 | 오탐률 분모 |
|---|---|---|
| `real` | 실제 이상 확인 | 포함 |
| `false` | 오탐 | 포함 (분자) |
| `check` | 판정 보류 — 현장 점검 필요 | **제외** — 섞으면 비율이 보류량에 흔들린다 |
| NULL | 미판정 | 제외 |

## 2. 데이터 모델 — Migration 0132

`tb_equipment_alarm_report` 에 `anomaly_label` / `labeled_by` / `labeled_at`.

- **정본은 `anomaly_label`, `is_false_alarm` 은 파생** — Node-RED 필터·
  경보분석 화면이 아직 그 컬럼을 보므로 유지하되, 라벨 기록 시 백엔드가
  동기화한다 (`false`→'Y', 그 외·해제→'N'. 해제도 'N' — 판정 무효인데
  파생 Y 가 남으면 라벨 없는 행이 계속 오탐으로 필터링된다).
- 백필: 기존 `is_false_alarm='Y'` 1,457건 → `'false'`. 라벨 값은 기존에
  기록된 사실이라 옮기되 **labeled_by/at 은 NULL** (판정자 소급 추정 금지
  — 0131 confirmed_by 와 같은 원칙).
- 부분 인덱스 `idx_alarm_report_labeled` (라벨된 행만 — 전체의 ~7%).

## 3. 판정 규칙 — 확인(0131)과의 차이

확인은 **사실 기록**이라 최초 1회만 보존하지만, 라벨은 **판단**이라
정정(변경·해제)을 허용한다. 대신 항상 마지막 판정자·시각을 남긴다.

- `PUT /crisis/alarm-reports/label` — label null = 해제
- UI: 이력 목록의 [실제][오탐][점검] 3버튼, 같은 라벨 재클릭 = 해제.
  **진행중 경보에는 제공하지 않는다** — 아직 판정이 이르다.

## 4. 오탐률 추이 — `GET /crisis/alarm-label-stats`

경보관리 4번째 탭 **"오탐 분석"** (`AlarmLabelStatsPanel`).

- 주 기준은 판정 시각이 아니라 **경보 발생 시각** — "그 주에 발생한 경보가
  얼마나 오탐이었나"가 실적 지표다. 백필분도 자연 편입.
- 판정 0건인 주의 오탐률은 **null** (차트 단선) — 0% 로 이으면 "오탐 없음"
  으로 오독된다.
- 판정률 5% 미만이면 안내 배너 — "판정이 쌓여야 오탐률이 의미를 갖는다"
  + **반복 경보 탭 상위부터 판정** 유도 (부록 B.4 축적 가속).
- 분류별 표에 **가중치 조정 유보 배지** — 판정 30건 미만 분류는
  `유보 (n/30)`. 조정 자체는 P2.

## 5. 이 사양이 하지 않는 것

- **가중치·임계 자동 조정 없음 (P1)** — 분류별 30건 미만에서 조정하면
  소표본 과적합 (로드맵 부록 B.4). P2 에서 z-score 가중·IForest 재학습
  반영 경로 설계.
- **채팅 오답 피드백과 합치지 않는다** — 그쪽은 인텐트 분류 품질
  (`feedback_wrong_answer_loop` 핵심 설계), 이쪽은 이상감지 판정 품질.
  라벨 저장소·화면·지표 모두 별도다.
- 라벨 이력(정정 로그) 없음 (v1) — 마지막 판정만 보존. 감사 요구가 생기면
  별도 이력 테이블.
