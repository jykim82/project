## p.2 — 왜 SLM인가

### 지금 상수도 관제실의 고민

- 태그 수천 개, 알람 수백 건 — **진짜 이상**은 무엇인가?
- 알람은 관제실에, 조치 기록은 수첩에 — **오탐 분석이 안 된다**
- 폐쇄망이라 **클라우드 AI는 반입 불가**

### SLM은 다릅니다

| | |
|---|---|
| 🖥️ **감시** | 실시간 계통도 · GIS 관망도 · ML 트렌드 분석 |
| 🔔 **알람** | 다변량 이상 감지 + 오탐·미검지 분석 + 조치 연동 |
| 🔧 **장비 고장 관리** | 사진 한 장으로 AI 진단 + 고장 케이스 DB |
| 🗺️ **관망 구축·조회** | 시설·태그·계통·GIS를 화면에서 직접 구축 |

> **모든 AI는 서버 안에서 구동됩니다.**
> 외부 인터넷 연결 0회 — 지도까지 오프라인 내장.

## p.3 — 핵심 차별화 4가지

### ① 사진 한 장으로 현장 진단
현장 설비 사진 업로드 → 장비 자동 식별 + 매뉴얼 인용 + 유사 고장 사례 매칭.
**폐쇄망에서 동작하는 유일한 멀티모달 AI 진단.**

`[화면]` 채팅 사진 진단 캡처

### ② 알람과 현장 조치를 잇다
자동 알람 ↔ 실제 조치 이력 대조 → 오탐 패턴 식별 →
**설비 교체 우선순위 Top 5** 자동 산출 (내용연수·MTBF·재발 융합).

### ③ 대화로 기록하는 장애 관리
"동문 가압장 2번 펌프 소음, 사진 첨부" — 시설·설비 자동 매칭,
조치 완료·보고서 작성까지 채팅으로. 모바일 **현장 모드** 지원.

### ④ AI는 참고, 판단은 데이터
AI 의견은 항상 별도 카드로 분리, 수치는 DB 실측값만 표시.
**Zero-Hallucination 원칙**으로 운영 판단의 신뢰를 지킵니다.

## p.5 — 제품 구성과 기술

### 필요한 만큼 선택하는 모듈형 구성

| 등급 | 구성 | 이런 사이트에 |
|------|------|---------------|
| **Basic** | 감시·알람·작업·GIS 기본 운영 | 신규 구축 사이트 |
| **Plus** | + 관망수리분석(EPANET) + 트렌드 비교 | 관망 데이터 보유 사이트 |
| **Enterprise** | + AI 멀티모달 진단 + 매뉴얼 RAG + 자동 보고서 | AI 차별화 활용 사이트 |

*설치 후 관리 화면 토글로 모듈 관리 — 등급 변경 시 재설치 불필요*

### 기술 스택 요약

- 웹 기반 (브라우저만으로 접속, 모바일 반응형)
- PostgreSQL + TimescaleDB 시계열 엔진
- 로컬 AI (LLM·비전·음성인식) — GPU 서버 1대로 구동
- Docker 기반 설치, region 멀티테넌시로 고객별 격리
- 무중단 업그레이드 경로 + 자동 모델 재학습 내장

- 온사이트 데모 지원

### 문의

- 공급사명 · 담당자 · 전화 · 이메일
- 상세 기능은 **제품 카탈로그**(16p) 참조

> 폐쇄망 안에서 완결되는 AI 상수도 통합 운영 플랫폼.

- **분량 근거**: 브로셔 표준 4~8p 중 6p 채택 — 3단 접지(양면 6면) 인쇄와

  단계(기능 상세·기술 사양·SKU·프로세스). 수치·사양 중복 기재 최소화.
