# 구축 워크스페이스 ↔ 모니터링 배치 동기화 정책

> **작성:** 2026-09-30 (사용자 요청 — "모니터링에서 보여지는 구성이 구축
> 워크스페이스에 싱크되도록". 중요 작업으로 롤백 절차 포함 기록)
> **결론:** 두 레이어 모두 **이미 단일 소스 구조로 동기화**되어 있음을
> 실측으로 확인. 데이터 변경 없음. 통신망에 향후 이탈을 즉시 보이게 하는
> **동기이탈 lint** 를 추가해 지속 보장.

## 1. 목적

구축 워크스페이스(`/setup/workspace`)의 용수계통·통신망 배치 그림이
실제 모니터링 화면(실시간 계통도 `/monitoring/flow` · 네트워크 토폴로지)의
배치와 항상 같아야 한다. 방향은 **모니터링에서 보이는 구성이 기준**.

## 2. 현 구조 — 어긋날 수 없는 이유

### 2.1 용수계통 (완전 동기 — 좌표 정본 공유)

- 정본: `tb_flow_diagram_node` 단 하나 (Migration 0120 캔버스 일원화)
- 모니터링 실시간 계통도: `GET /flow-diagram/nodes` (경위도 그대로)
- 워크스페이스 캔버스: `GET /canvas/layout` (같은 테이블을 px 변환 —
  변환은 `canvas_crud.py` 소유, 레벨 240px·형제 56px 고정 선형)
- **양방향**: 어느 화면에서 드래그해도 같은 테이블에 저장 → 즉시 상호 반영

**검증 (2026-09-30 실측):** 노드 집합 122=122 완전 일치. 경위도↔px 선형
회귀 최대 잔차 **x 0.0000px / y 0.0000px** — 수치상 완전 동기.

### 2.2 통신망 (구성 동기 + 이탈 감시)

- 모니터링 계층형 토폴로지: `network-layers.ts` 계층 선언으로 **계산 배치**
  (저장 없음)
- 워크스페이스 링크 에디터: `tb_canvas_layout` **저장 배치** (Migration 0126,
  표시 전용)
- 두 화면의 구성 통일 장치: `layout.ts layerLayout()` 이 같은
  `network-layers.ts` 를 단일 소스로 사용 (2026-08-03 — "구축에서 그린 것 =
  모니터링에서 보이는 것"). 툴바 **계층 정렬** 버튼이 저장 배치를 모니터링
  계층 구성으로 재생성

**검증 (2026-09-30 실측):** 저장 배치 295대 전부 layerLayout 계산값과
**불일치 0대** — 현재 완전 동기.

**이탈 경로와 감시:** 워크스페이스에서 수동 드래그하면 저장 배치만 바뀌어
조용히 이탈한다 → lint 배지에 **"동기이탈 N대"** 추가 (2026-09-30).
이탈 발생 시 배지가 즉시 amber 로 바뀌고, **계층 정렬 버튼 1회로 복원**.
의도적으로 커스텀 배치를 쓰는 현장은 배지를 정보로만 취급하면 된다
(강제 복원 없음 — 수동 배치도 유효한 운영 선택).

## 4. 운영 규칙

1. 통신망 배치를 모니터링과 다시 맞추는 표준 수단은 **계층 정렬 버튼**
   (= layerLayout = 모니터링 구성). 별도 스크립트 금지 — 경로 이원화 방지
2. 계층 순서·색을 바꿀 때는 `network-layers.ts` **한 곳만** 수정 —
   모니터링·워크스페이스가 함께 바뀐다
3. 계통도는 정본이 하나라 동기화 작업 자체가 존재하지 않는다 — "계통도
   동기화 스크립트" 류 제안은 구조 오해이므로 기각
