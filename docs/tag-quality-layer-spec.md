# 태그 품질 계층 (Tag Quality Layer) 사양 v1

> **상태:** v1 — **P1·P2·P3 구현 완료 (2026-07-24)**
> **목적:** 계측 원천 데이터의 품질 이상(포화·고착·무신호·반전·이탈)을 **단일
> 파이프라인**으로 상시 감시하고, 태그별 품질 상태를 판정·학습·알람·화면이
> **공유**하게 한다. 개별 증상마다 규칙을 덧대는 대응(두더지잡기)을 끝내는
> 구조적 해결.
> **관련:** `docs/review-items.md` 2026-07-23 데이터 품질 3건,
> `docs/trend-baseline-gbt-spec.md`(hm 게이트), error-management E-051

---

## 1. 배경 — 한 뿌리에서 나온 사건들 (2026-07)

| 사건 | 증상 | 당시 대응 (개별 규칙) |
|---|---|---|
| E-051 | 계측 개시 이전 노이즈가 기준선 오염 → +1257% 오판 | 이상 진단 SQL `tag_scale` 하한 |
| 성상1 유출압력 | 계측 상한(10) 이틀 포화 — 6/1 이후 7주 간헐 재발. 무경보 | `_detect_sensor_saturation` (스캔 시점 감지) |
| 죽동 정전 DI | 30일 상시 ON → power_fault 상시 오경보 (동류 10곳+) | DI 상시 ON 게이트 (스캔 시점 제외) |
| 저신호 태그 | 정확도% 0 왜곡 | 평가 화면 low_signal 배지 |

공통점: **원천 계측 품질 문제**인데 발견 시점마다 소비처 한 곳에만 규칙이
추가됨. 다음 유형이 나오면 또 사용자 육안 발견에 의존한다. 진행 중 상시
감시("진행 중엔 침묵" 공백)와 소비처 간 일관성(스캔은 알고 트렌드 카드는
모름)이 없다.

## 2. 목표 / 비목표

- **목표:** ① 검사 규칙을 한 곳에 통합 ② 태그별 품질 상태를 테이블로 상시
  유지 ③ 하류(진단·요약·기준선·알람·건강성)가 같은 상태를 소비
- **비목표:** 계측기 자체 수리(현장 소관), SCADA 원계통 설정 변경,
  실측값 보정/대체값 생성(품질 계층은 **표시·제외**만, 값 조작 금지)

## 3. 검사 규칙 5종 (P1)

기존 개별 구현을 이관·통합한다. 창·임계는 전부 config(환경변수) — 하드코딩 금지.

| # | 규칙 | 판정 (기본값) | 출처 |
|---|---|---|---|
| Q1 | 센서포화 | 최근 6h 5분버킷 80%+ 가 min·max 모두 90일 관측 상한(±0.1%) | anomaly_scan 이관 |
| Q2 | 신호고착 | 최근 6h 90%+ flat(min=max) AND 직전 7일 변동 존재 | anomaly_scan 이관 |
| Q3 | 무신호/DEAD | 7일 전체 val≈0 또는 데이터 없음/부족 | `_detect_data_quality_issues` 이관 |
| Q4 | DI 반전/고착 | 장애 그룹 DI 7일 on 비율 ≥95% | DI 게이트 이관 |
| Q5 | 값 이탈 | 최근 3일 중앙값×10% 미만 지속(E-051 계열) 또는 물리 범위 초과 | tag_scale 일반화 |

판정 결과: `정상` / `의심(suspect)` / `불량(bad)` + 사유 코드 + 지속 시작
시각. 설정/SET·적산 태그는 대상 제외(기존 규칙 승계).

## 4. 저장 — `tb_tag_quality` (Migration 0115)

```
region, tagsn (PK), status(normal|suspect|bad), reason(코드), detail(텍스트),
since(품질 이상 시작), checked_at, window_stats(jsonb — 판정 근거 박제)
```
- 이력은 P1 에서 현재 상태만(UPSERT). 상태 전이 이력은 P3 검토(용량 대비 가치).

## 5. 배치 — backend 내장 루프 (IForest 패턴)

- `ai_server` 내 `_tag_quality_loop`: 시작 후 첫 실행 + **1시간 주기**.
  외부 cron 없음(baseline cron 미등록 5주 사고의 교훈 — 컨테이너 자족).
- 전 태그 1회 검사 SQL 은 cagg_5min_raw_stats_ai 기반 (SCAN_ALL 무거운
  365일 쿼리와 무관, 독립 실행 수초대 목표).

## 6. 소비처 연동 (Phase)

### P1 — 일원화 (감지→테이블→기존 노출)
- 이상 진단/AI 요약/대시보드의 data_quality_issues 를 **테이블 조회로 대체**
  (스캔 시점 재계산 제거 — SCAN_ALL 부하 절감 부수효과)
- 설비 장애 DI 게이트도 테이블 참조로 전환
- 채팅 이상 진단 답변·AI 현황 요약 문구는 기존 유지 (issue_type 동일)

### P2 — 판정·학습 보호
- **기준선 학습 제외**: `_hourly_pattern_baseline`·`trend_baseline` 학습 시
  품질 불량 구간(since~) 제외 → 오염 원천 차단 (성상1 "정상 복귀를 주의↓
  역판정" 재발 방지)
- **트렌드 카드 배지**: 대상 태그 품질 불량 시 평소 대비/전망 배지 대신
  "계측 품질 의심 — 판정 신뢰 불가" (violet 데이터 품질 톤)

### P3 — 알람·자산 연동 (별도 결정 후)
- 품질 불량 태그의 값 기반 자동 알람 억제 + "계측 품질" 알람 분리
  (`feedback_no_auto_alarm_link` 원칙 준수 — 기존 알람 자동 해제는 안 함)
- 설비 건강성: 품질 불량 지속 태그 → 계측기 점검 후보 신호로 연결

## 7. 제품 관점

  검증** — `slm-setup-phase-spec` 확장으로 분리 추진 (review-items 참조)
