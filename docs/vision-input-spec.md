# 비전 입력 계층 사양 v1 — 로드맵 E 재정의 (명판 우선)

현장 사진에서 텍스트·수치를 추출해 **기존 입력 경로의 초안**으로 채운다.
신규 OCR 스택 없이 로컬 gemma4 비전(E-025 파이프라인) 재사용 — 폐쇄망 완결.

**사전 검증 (2026-07-29, 실물 명판 5장)**: 인쇄 활자·정상 화질은 실용 수준
(ULVAC·HANIL 한글·DOOCH 전 필드 정확, 장당 33~60초). 리스크 2건 실증 —
① 흐린 사진에서 null 대신 그럴듯한 값 생성(HYOSUNG) ② 명판에 없는 지식
추정(WALRUS "MADE IN TAIWAN"). → 보정 계층·사람 확인이 필수인 근거.

## 1. 원칙

- **추출은 초안, 확정은 사람** — 모든 항목(항목명·수치 포함)을 저장 전
  수정 가능. **수치 수정은 필수 제공** — OCR 오판(제조번호 8↔6 실증)은
  전제 조건이다.
- **인식한 수준까지만 기록** — 못 읽은 항목은 비운다. 명판 밖 지식으로
  채우지 않는다 (프롬프트 금지 + 필드 화이트리스트 없음 — 자유 키-값).
- **원본 사진이 정본** — 값이 의심되면 사진을 본다. 첨부 보관 필수.

## 2. 명판 → 설비 제원 (P1 — 구현 완료 2026-07-29)

구현: `slm/endpoints/nameplate.py` (extract/save) + `NameplateScanDialog`
(설비 관리 행 명판 버튼). 검증: DOOCH 실물 UI 왕복 — 추출→편집 표→표준
매핑, HANIL 13항목(토출경·절연등급 포함) 손실 없이 추출. 저장은
meta.nameplate + nameplate_photo_url(기존 컬럼) + 사진 파일.

**동적 키-값** — 명판 항목은 제조사마다 다르다 (실증: 토출경/절연등급/
베어링/오일용량 등 고정 스키마 밖 항목 다수). 고정 컬럼에 끼워 맞추지
않는다:

1. 설비 선택 → 명판 촬영 (현장 모드·인스펙터 설비 탭)
2. gemma4 추출 — "명판에 보이는 라벨: 값" 쌍 그대로 (단위 포함 원문)
3. 확인 화면: 사진 옆 키-값 목록 — 행 추가/삭제/항목명·값 수정 개방
4. 저장: `tb_equipment_info.meta.nameplate` (jsonb — 스키마 변경 없음)
   + 사진 `tb_file_storage`/`files/facility/` + 촬영·추출·수정 이력
5. **표준 키 승격**: 별칭 사전(MODEL=형식명=TYPE→model, 정격출력→
   rated_output 등)으로 핵심 필드만 파생 — 교체 우선순위·내용연수·검색이
   사용. 원문 키-값이 정본, 승격 매핑은 확인 화면에서 수정 가능
6. 기존 수기 제원과 불일치 시 나란히 표시 — 사람이 선택

## 3. 보정(검증) 계층 — 백엔드 모듈

- 범위 룰: kW·전압(220/380/440 표준값)·주파수(50/60)·날짜 형식
- DB 대조: 제조사명 퍼지 매칭, 동일 모델 기존 제원과 diff
- 이중 추출 일치 검사 — 불일치 필드 "저신뢰" 마킹
- (계기판) 추출 수치 vs SCADA 현재값 물리 범위 대조 → 이탈 시 재촬영 요구

## 4. 후속 출구 (P2+)

- 계기판 → 점검 기록 초안 (+SCADA 대조로 계측기 드리프트 검출)
- 추출값 → 엑셀 정리 (기존 openpyxl 재사용)
- 손글씨 → 보고서 텍스트 (필기 정확도 검증 후 채택 여부 — 음성 STT 가
  이미 있어 우선순위 낮음)

## 5. 하지 않는 것

- 신규 OCR 스택(EasyOCR/Paddle) 반입 없음 · 자동 저장 없음(확인 필수) ·
  클라우드 비전 API 없음
