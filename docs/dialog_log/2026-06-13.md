# 2026-06-13 세션 대화 로그

## 1. 태그 모니터링 — 네트워크 진단 vs PLC 데이터 알람 계층 분리 (이상 카테고리 6→5)

### 배경 / 사용자 지적
- 사용자: 태그 모니터링에서 "네트워크단절" 필터 시 신평2 소블록 유량계는
  데이터가 매분 갱신되는데도 통신이상으로 표시됨 → "실제 알람이 발생했나?"
- 검토 결과 실제 현장 알람 아님. `tb_network_status`(AI 서버→현장제어반 ping
  진단)에서 `plc_37` ping Timeout → A소스 로직이 plc_37에 매핑된 모든 측정
  태그(유량계 포함)에 `network_down` 전가. 현장 통신이상 DI=0, 진행 알람 없음.
- 사용자 3대 원칙: ① `tb_network_status`는 정상 네트워크 진단(테스트 데이터 아님)
  ② 유량계/PLC 통신 알람은 TM master 등 통신장비가 판단해 DB 기록(DI 태그)
  ③ **네트워크 진단기능과 실제 PLC 데이터 알람상태는 구분되어야 함**.

### 결정 — 안 A (완전 분리)
- 3계층 정의: L1 네트워크 진단(ping)/L2 현장 통신 알람(DI·TM master)/L3 측정 데이터.
- 태그 모니터링 = **L3 전용**. `network_down`(L1)을 측정 태그 이상 배지에서 제거
  (6→5). ping 경로와 데이터 경로(TM master/LTE)는 물리적으로 달라 ping 실패해도
  데이터 정상 수신 가능 → 전가 시 신선 데이터 태그 오표시.
- A소스 영향분석 로직(`equipment_failure_impacts`)은 백엔드 **보존**(네트워크
  건강 화면 재사용 여지). 절충안(별도 컬럼 병기)은 "다시 섞인" 인상 우려로 미채택.
