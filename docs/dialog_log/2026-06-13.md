# 2026-06-13 세션 대화 로그

## 1. 태그 모니터링 — 네트워크 진단 vs PLC 데이터 알람 계층 분리 (이상 카테고리 6→5)

### 배경 / 사용자 지적
- 사용자: 태그 모니터링에서 "네트워크단절" 필터 시 신평2 소블록 유량계는
  데이터가 매분 갱신되는데도 통신이상으로 표시됨 → "실제 알람이 발생했나?"
- 검토 결과 실제 현장 알람 아님. `tb_network_status`(AI 서버→현장제어반 ping
  진단)에서 `plc_37` ping Timeout → A소스 로직이 plc_37에 매핑된 모든 측정
  태그(유량계 포함)에 `network_down` 전가. 현장 통신이상 DI=0, 진행 알람 없음.
- 사용자 3대 원칙: ① `tb_network_status`는 정상 네트워크 진단(테스트 데이터 아님)
  ② 유량계/PLC 통신 알람은 TM master 등 통신장비가 판단해 DB 기록(DI 태그)
  ③ **네트워크 진단기능과 실제 PLC 데이터 알람상태는 구분되어야 함**.

### 결정 — 안 A (완전 분리)
- 3계층 정의: L1 네트워크 진단(ping)/L2 현장 통신 알람(DI·TM master)/L3 측정 데이터.
- 태그 모니터링 = **L3 전용**. `network_down`(L1)을 측정 태그 이상 배지에서 제거
  (6→5). ping 경로와 데이터 경로(TM master/LTE)는 물리적으로 달라 ping 실패해도
  데이터 정상 수신 가능 → 전가 시 신선 데이터 태그 오표시.
- A소스 영향분석 로직(`equipment_failure_impacts`)은 백엔드 **보존**(네트워크
  건강 화면 재사용 여지). 절충안(별도 컬럼 병기)은 "다시 섞인" 인상 우려로 미채택.

### 변경 파일
- `docs/tag-monitoring-spec.md` v1.5 — §3.0.1 계층 분리 원칙 추가, 카테고리 5종화,
  §3.1/§6.1/Phase 2/변경이력 동기화.
- `slm/endpoints/tags.py` — `_ANOMALY_LABELS` 에서 `network_down` 제거(주석으로
  L1/L2 제외 사유 명시). `equipment_failure_impacts` 루프는 `_ANOMALY_CODES`
  게이트로 자동 스킵.
- 프론트 `src/lib/types/tag.ts` — `AnomalyCode` 유니온·`ANOMALY_CATEGORIES`
  에서 `network_down` 제거(5종). 주석에 L1/L2 제외 사유.
- 프론트 `src/app/(dashboard)/monitoring/tags/page.tsx` — `ANOMALY_ALL` 을
  `ANOMALY_CATEGORIES` 파생으로 변경(드리프트 방지) + import 추가.

  사라짐, 콘솔 에러 0. (도중 turbopack 증분 캐시 wedge → 파일 touch 로 해소.)

## 2. 네트워크 화면 — L1→L3 역추적 "영향 측정 태그" 섹션 (권장안 구현)

### 배경
- 1번 계층 분리로 태그 모니터링에서 ping 진단을 분리. 단, ping 죽은 장비 뒤에
  실제로 어떤 측정 태그가 매달려 있고 그 값이 살아있는지 확인할 자리가 필요.
- L1 진단은 이미 `/network` 화면에 존재(`/network/devices` is_alive/rtt_ms,
  topology, comm-alarms). 누락된 건 **장비 → 영향 측정 태그 연결**뿐 → 신규 화면
  불필요, 최소 보강으로 결정.

### 변경 파일
- `slm/endpoints/network_crud.py` — 신규 `GET /network/devices/{equipment_id}/tags`.
  `tb_equipment_tag_map`+`tb_tag_info` JOIN, LATERAL 로 최근 7일 최신값
  (`idx_tag_raw_tagsn_time`). 현재값/logtime/alarm_tag_yn 직렬화.
- 프론트 `src/lib/types/network.ts` — `DeviceTag` 타입 추가.
- 프론트 `src/lib/api/network-api.ts` — `fetchDeviceTags()` 추가.
- 프론트 `src/components/network/AffectedTagsSection.tsx` — 신규. 장비 선택 시
  지연(STALE 15분) 표시, `알람` 배지, 현재값+단위 렌더.
- 프론트 `src/components/network/NodeDetailPanel.tsx` — 정보 탭 하단에 섹션 삽입.
- `docs/tag-monitoring-spec.md` v1.6 — §3.0.1 에 L1→L3 역추적 위치 명시 + 변경이력.

### 검증

- 프론트(Playwright): `/network` 계층형 뷰에서 `plc_37` 노드 선택 → 장비 상세

  DI `알람` 배지 확인. "ping 장애 ≠ 데이터 손실" 시각 입증. tmp 스크린샷 저장.
