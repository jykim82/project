# 2026-07-12 세션 대화 로그

## 이상감지 스캔 질의 오라우팅 수정 (장애 기록 확인)

### 사용자 요청
- "'행정 배수지 센서이상 스캔' 질의가 장애 기록 확인으로 잘못 넘어가고 있어"

### 원인
프런트 `hooks/use-chat-submit.ts`의 `isFaultRecordIntent()`가 "이상"(장애 키워드)
+ "배수지"(시설 키워드) 조합만 보고 장애 기록 초안(`/chat/fault/draft`)으로 분기.
"**스캔**"이 붙은 **이상감지 조회 인텐트**(ANOMALY_SCAN_ALL)를 걸러내는 제외 규칙이
없었음. 백엔드/`/ask/stream` 자체는 ANOMALY_SCAN_ALL 로 정상 분류(검증 완료)했으나,
프런트가 애초에 `/ask/stream` 을 호출하지 않고 fault/draft 로 보냄.

### 변경
- `use-chat-submit.ts` `isFaultRecordIntent()`에 이상감지/분석 조회 키워드 제외 추가:
  `(스캔|감지|진단|점검|분석|예측|이상치|패턴|추이|통계|현황|이력)` 포함 시 제외.
  단 명시적 기록 표현 `(기록|저장|남겨|등록|발생|났|발견)` 이 있으면 유지.
- `docs/equipment-fault-tracking-spec.md` §6 키워드 감지 규칙을 현행 코드에 맞게 갱신
  (기존 "기록 포함 필수" 서술은 실제 코드와 불일치했음 — 정정).

### 검증 (실제 브라우저)
- "행정 배수지 센서이상 스캔" → `/api/proxy/ask/stream` 호출, 이상 스캔 뷰 렌더
  (이상 1 / 주의 1 / 정상 9 / 통신장애 7, ML·데이터품질 카드). "장애 기록 확인" 카드 없음.
- 회귀: "신평 배수지 판넬 전원이상 발생했어" → `/chat/fault/draft` 호출, 장애 기록 확인 카드
  정상 표시 (기록 표현 "발생" 으로 제외 미적용).

## 배수지 충전 상태 용수공급 가능시간 표기 개선

### 사용자 질문
- "난지관광 배수지는 수위가 11%인데 충전 상태이면 용수공급 가능시간이 24시간으로 나타나도록 되어 잇나"

### 원인·설계 확인
Node-RED 플로우가 `tb_service_reservoir_status` 에 계산·저장. `net = 유출률 − 유입률 ≤ 0`
(유입 ≥ 유출 = 충전 상태)이면 `status=CHARGING`, `total_supply_time=24h` **고정값**.
24h 는 실제 소진 시간이 아니라 "소진 안 됨" 플레이스홀더. DB 실측 난지관광 = 24.00/CHARGING.
저수위(11%) 게이지 옆 "24.0h" 는 공급 여유로 오독 소지 → 사용자 확인 후 표기 개선.

### 변경 (사용자 선택: "충전 중 배지로 대체")
프런트 4곳에서 CHARGING 이면 24h 숫자 대신 **"충전 중 ↑ / 소진 없음"** 표기,
저수위(≤12%, WaterLevelGauge 동일 임계)면 "⚠ 수위 N% 저수위 주의" 병기:
- `GisDetailPanel.tsx` (상세 패널) / `GisFacilityCard.tsx` (마커 카드)
- `GisFacilityPopup.tsx` (시설 팝업) / `FlowMonitoringGraph.tsx` (계통도 툴팁·오버레이)
백엔드 무변경(status 이미 내려줌). 사양: flow-diagram-mode-spec §7.3.

### 검증 (실제 브라우저 — 난지관광)
- 상세 패널: "충전 중 ↑ / 소진 없음 (유입 ≥ 유출) / ⚠ 수위 11% 저수위 주의"
- 마커 팝업: "공급시간 충전 중" (24.0h 제거). 전체에서 "공급시간 24.0" 문자열 0건.
