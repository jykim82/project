## IForest 이상탐지 모델 영속화 + 평가 (사양 + 구현 + UI)

### 사용자 요청
- "isolation forest도 평가할수 잇나?" — GBT baseline 처럼 IForest 도 평가 가능한지.
- "IForest는 현재 인메모리 방식의 재학습이 맞는건지 검토해줘" — 인메모리 재학습 적정성 검토.
- "영속화를 해야 통계가 나오고 검증이 되는거 아니야?" — 영속화가 통계·검증의 전제 확인.
- "응 해당 사양으로 사양서를 작성하고 구현해줘. 확인할수 있는 ui도 동일하게 필요해"
  — 사양서 작성 + 구현 + baseline-eval 스타일 평가 UI.

### 핵심 결론
- IForest 는 비지도라 "정확도%" 불가 → **calibration_err(관측 이상률 vs 목표
  contamination 편차) + coverage%** 를 P1 헤드라인 지표로. 레이블 기반 탐지
  정밀도(오탐율)는 P2 로 보류.
- 인메모리 단점 3가지(콜드스타트 무탐지/지표 미축적/검증 불가) → 디스크 .pkl
  영속화 + 지표 DB 적재로 해소. GBT baseline 패턴(CLI/cron/run·metric 테이블/
  eval 엔드포인트/eval UI) 그대로 미러링.

### 산출물

- 백엔드: `anomaly_iforest.py` (영속화·지표·CLI `python -m anomaly_iforest train`),
  `endpoints/iforest_eval.py` (신규, `/admin/iforest-eval` + `/group-models`),

  tb_iforest_model_metric), `0092_iforest_eval_menu.sql`(메뉴 M100-14)
- 프런트: `admin/iforest-eval/page.tsx`, `lib/api/iforest-eval-api.ts`,
  `sidebar-menus.ts`(M100-14 fallback)
- 운영: `docs/operations/iforest-train-cron.md` (신규)
- CLAUDE.md 인벤토리 등록(spec + cron 가이드)

## "AI 모델 평가" 통합 화면

### 사용자 요청
- "트렌드 모델평가과 iFOREST 모델평가를 AI 모델 평가로 통합하고 통합 페이지에서
  선택하여 전환하도록 구성해줘"
- 셀렉터 라벨 "트렌드 정상기대값(GBT)" 로 표기 수정 요청.
- (질문) 트렌드 평가의 "lag확보%" 약자 → lag = 시계열 시차값(자기 과거값),
  확보% = 그 lag 를 실제 확보해 예측에 쓴 행 비율(lag_avail_pct).
