## IForest 이상탐지 모델 영속화 + 평가 (사양 + 구현 + UI)

### 사용자 요청
- "isolation forest도 평가할수 잇나?" — GBT baseline 처럼 IForest 도 평가 가능한지.
- "IForest는 현재 인메모리 방식의 재학습이 맞는건지 검토해줘" — 인메모리 재학습 적정성 검토.
- "영속화를 해야 통계가 나오고 검증이 되는거 아니야?" — 영속화가 통계·검증의 전제 확인.
- "응 해당 사양으로 사양서를 작성하고 구현해줘. 확인할수 있는 ui도 동일하게 필요해"

### 핵심 결론
- IForest 는 비지도라 "정확도%" 불가 → **calibration_err(관측 이상률 vs 목표
  contamination 편차) + coverage%** 를 P1 헤드라인 지표로. 레이블 기반 탐지
  정밀도(오탐율)는 P2 로 보류.
- 인메모리 단점 3가지(콜드스타트 무탐지/지표 미축적/검증 불가) → 디스크 .pkl
  영속화 + 지표 DB 적재로 해소. GBT baseline 패턴(CLI/cron/run·metric 테이블/
  eval 엔드포인트/eval UI) 그대로 미러링.

## 알람 위기대응 팝업 "발생원인/대응방안 null" 폴백 fix

### 사용자 요청
- "죽동(가) 흡수정수위 LL 발생 알람에 발생 원인과 대응 방안이 NULL 인 이유는?"
- 원인 확인 후 "1번(프런트 견고화)을 우선 진행해줘".

### 원인
- 팝업(`AlarmAnalysisDetail`)은 `diagnosed_msg` HTML 을 최우선 파싱하고
  diagnosed_msg 가 없을 때만 구조화 컬럼으로 폴백(all-or-nothing).
- 이 알람의 `diagnosed_msg` 는 생성 시 cause/action 변수 누락으로
  `<strong>(발생원인)</strong>&nbsp;null` 처럼 문자열 "null" 이 박힘.
  반면 구조화 컬럼 `diagnosed_cause`/`countermeasure` 에는 정상값 존재.
- DB 14,559건 중 10건이 diagnosed_msg 에 "null" 박힘 → 전부 구조화 컬럼은 정상.

### 변경 (프런트만)
- `AlarmAnalysisDetail.tsx` `parseDiagnosedMsg(html, fallbacks)` 로 확장.
  `isNullish`(""/null/undefined/none/nan/-) 값은 `resolveValue` 로 구조화
  컬럼(발생원인→diagnosed_cause, 대응방안→countermeasure) 치환, 폴백도 없으면 항목 제거.
- infobox 엔트리·직접 text 블록 둘 다 "(키) null" 패턴 가드.
- 백엔드/데이터 무변경(2번은 보류). 향후 동일 패턴 재발도 자동 방어.

### 검증
- Playwright 위기대응 팝업: (발생원인) "배수지 유출량 증가…", (대응방안) "대응 불필요"
  정상 표시, "null" 리터럴 0, 콘솔 에러 0. tsc 신규 에러 0.
