## 4. NextAuth 멀티 호스트 지원 — 화면 깜빡임 fix
- **증상**: 사용자가 `https://192.168.219.105:3000/admin/menus` 에 머물면 약
  70~80초 주기로 전체 화면 깜빡임 + 스크롤 위치 초기화.
- **원인**:
  - 컨테이너 `NEXTAUTH_URL=https://localhost:3000` 고정
  - 사용자 실제 접속: LAN IP `192.168.219.105:3000`
  - 쿠키 `__Secure-next-auth.callback-url=https%3A%2F%2Flocalhost%3A3000` 으로
    callback URL 과 요청 origin 미스매치 → SessionProvider 가 주기적으로
    재발급 시도하면서 컴포넌트 reflow 발생.
- **조사 경로**:
  - Playwright 로 dashboard·GIS·admin/menus 각각 2~3분 모니터링 → reload 0회
    (localhost 접속이라 미스매치 미발생). 코드만 봐서는 단서 없음.
  - 사용자 DevTools Network 캡처 — `data-quality?region=R01` 14회/16분 호출.
    Initiator `api-client.ts:42`. 호출 간격 약 70초.
  - Request Headers 확인 → `cookie: __Secure-next-auth.callback-url=...localhost:3000`
    이 결정적 단서. NEXTAUTH_URL 환경 변수가 localhost 로 고정된 것 확인.
- **해결**:
  - `src/app/api/auth/[...nextauth]/route.ts` — request host 헤더로 매 요청마다
    `process.env.NEXTAUTH_URL` 런타임 오버라이드. `x-forwarded-proto` 우선,
    없으면 localhost 만 http 로 다운그레이드.
  - `src/lib/auth.ts` — `useSecureCookies: true` 명시. 멀티 호스트 모두 HTTPS
    가정이라 host-only 자동 스코핑으로 호스트별 별도 세션.
- **사용자 액션 필요**: LAN IP 에서 1회 로그아웃 → 재로그인 (기존 stale
  callback-url 쿠키 갱신용).

## 5. LAN IP 깜빡임 — 진짜 근본 원인 발견 + 수정 (E-034)
- **재현 지속**: 사용자 로그아웃·재로그인 후에도 동일 증상 + Edge 에서도 동일
  → 브라우저 무관 / NextAuth 멀티 호스트 fix 만으로 부족.
- **결정적 단서 (Edge DevTools 스크린샷)**:
  - `webpack-hmr` websocket 이 3회 재연결 (web-socket.ts:5...)
  - Next.js 콘솔: **"Blocked cross-origin request from 127.0.0.1 to /_next/*
    resource. To allow this, configure allowedDevOrigins"**
  - "Finish: 5.08s" + DOMContentLoaded 라벨 → 페이지가 방금 reload 됨
- **원인 2 중 복합**:
  1. `next.config.ts` `allowedDevOrigins: ["*.trycloudflare.com"]` 뿐 →
     LAN IP origin 의 `/_next/*` 요청 차단 → HMR ws reconnect 반복 →
     Turbopack stale chunk 감지 시 페이지 reload
  2. cert SAN 에 `localhost / 127.0.0.1 / ::1` 만 → LAN IP wss 검증 불안정
- **해결**:
  1. `next.config.ts` `allowedDevOrigins` 에 사설망 와일드카드 추가 —
     `127.0.0.1 / 192.168.*.* / 10.*.*.* / 172.16~31.*.*`
  2. `certs/localhost.pem` 재발급 — 호스트의 모든 LAN IP 를 SAN 에 포함
     (`192.168.219.105` 외 4개 인터페이스)
  3. frontend 컨테이너 재시작 → 새 cert + config 즉시 적용
- **검증**: 사용자가 `https://192.168.219.105:3000/admin/menus` 에서 정상
  확인.
- **추가 산출물**:
  - `certs/README.md` — 신규 머신 셋업 + cert 재발급 가이드 + E-034 참조
  - `docs/error-management.md` E-034 신규
  - `.gitignore` 에 `/certs/*.pem` `/certs/*.exe` 추가 (private key 보호)
