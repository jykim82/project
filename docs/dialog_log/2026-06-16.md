## 트렌드 정상 기대값 GBT baseline 고도화 (P1+P2)

### 사용자 요청 (Q&A 흐름)
- "아나로그 향후 추세 알고리즘 적용돼 있지?" → 현황 설명.
- XGBoost 검토 → **트리는 외삽 불가**라 forecast(향후 전망)는 선형 유지,
  **GBT 는 평소 대비(정상 기대값) 전용**으로 결정. "응 적용해줘. 산출 방식
  설명도 갱신(xAI)."
- "데이터 많은데 LightGBM 대비?" → 시간 집계(수백만 행) 규모에선 동급,
  **신규 의존성 0 인 sklearn HistGradientBoosting 채택**.
- 데이터셋 사양·갱신주기·성능 평가 화면 요청 → "추천안으로 진행해줘."
  ("V1/V2 화면 차이 없음, 주1회 재훈련 OK, 평가 지표만 수치로 확인" 확정).

### 핵심 설계
- baseline 기대값을 `hourly_mean` → **GBT 예측값**으로 교체. z-score 판정·
  forecast·UI·알람은 불변. 모델 없음/데이터부족/skip → hourly_mean 폴백.
- **anomaly masking 회피**: 동시점 공측정(유입↔유출↔수위) 피처 제외, 캘린더
  + 시차 자기lag + 시설 식별만. 고카디널리티 tagsn 제외(lag 가 개별성 반영).

- 백엔드 `slm/endpoints/trend.py` — xAI comparison 블록 기대값 산출방식 표기.

  `app/(dashboard)/admin/baseline-eval/page.tsx`(신규),

### 컬럼 의미 설명(회차 히스토리)
- hourly_mean = 같은 holdout 을 옛 방식(요일·시각 평균)으로 예측한 비교군 MAE.
- 개선% = (hourly_mean − GBT)/hourly_mean. GBT 오차 감소율.
- 커버리지% = 실제값이 밴드(예측±2σ) 안에 든 비율(calibration, 목표≈95%).
