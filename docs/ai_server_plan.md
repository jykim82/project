# ai_server_plan.md
SLM 기반 운영 질의 응답 서버 설계 문서

---

## 1. 문서 목적

본 문서는 `ai_server.py`의 설계 의도, 역할 범위, 금지 영역을 명확히 정의한다.  
이 서버는 LLM/SLM을 활용하지만, 지능형 판단 시스템이 아니다.

이 문서의 목적은  
“왜 이렇게 만들었는가”를 코드보다 먼저 설명하는 데 있다.

---

## 2. 서버의 정체성

### 2.1 이 서버는 무엇인가

- 운영 데이터를 대상으로 한 질의 실행 서버
- 자연어 질의를 정의된 정책(JSON)에 따라 해석
- SQL 실행 결과를 사람이 이해할 수 있게 설명

### 2.2 이 서버는 무엇이 아닌가

- 이상/정상 판단 시스템
- 예측·추론·보정 시스템
- 정책 결정 시스템
- 임계값 자동 산정 시스템

---

## 3. 핵심 설계 철학

### 3.1 역할 분리 원칙

| 구성 요소 | 책임 |
|---|---|
| example3.json | 정책 / 의도 / 구조 정의 |
| ai_server.py | 실행 / 조립 / 검증 |
| SQL | 사실 결정 |
| SLM | 설명 / 요약 / 문장화 |
| 사용자 | 판단 / 의사결정 |

결정 가능한 것은 시스템이 하고,  
판단이 필요한 것은 사람에게 남긴다.

---

### 3.2 SLM 사용 원칙

- SLM은 답을 결정하지 않는다
- SLM은 이미 결정된 결과를 설명한다
- 단정적 판단 표현 금지
- 근거 없는 요약 금지

---

## 4. 전체 처리 흐름

ai_server.py의 질의 처리 흐름은 다음과 같다.


본 흐름에서 **의미 판단은 수행하지 않으며**,  
모든 분기는 실행 결과 또는 데이터 존재 여부에 기반한다.

## 5. 입력 검증 및 질의 실패 처리 원칙

### 5.1 필수 파라미터 누락

- sitename 누락
- facilitytype을 추론해야 하는 상황

처리 방식:
- SQL 실행 금지
- 오류 응답 반환
- 사용자에게 질의 보완 요청 메시지 제공

---

### 5.2 매칭 실패

- 질문이 example3.json의 어떤 INTENT와도 매칭되지 않는 경우

처리 방식:
- SQL 실행 금지
- 오류 응답 반환
- 추천 질문(recquestions) 제공 가능

---

## 6. 공통 오류 처리 규칙

본 문서에서 정의하는 모든 오류는  
**서버 로그로 기록되며**, 동시에 **API 응답으로도 반환**된다.

로그 기록과 API 응답은 서로 다른 목적을 가진다.

- 로그: 운영자 및 개발자를 위한 내부 진단 정보
- API 응답: 사용자 및 UI를 위한 안내 메시지

내부 오류의 상세 정보(스택 트레이스, SQL 원문 등)는  
API 응답에 포함하지 않으며, 로그에만 기록한다.

### 로그 레벨 가이드

- INFO: 조회 결과 없음, 정상 흐름 내 정보성 이벤트
- WARNING: 사용자 입력 부족, 매칭 실패
- ERROR: DB 오류, SQL 실행 오류, JSONB 스키마 불일치

본 섹션은 **질의 의미와 무관한 실행 단계 오류**에 대한  
ai_server.py의 공통 처리 규칙을 정의한다.

이 규칙은 모든 INTENT에 공통 적용되며,  
example3.json에 정의하지 않는다.


---

### 6.1 DB 접속 오류

- 데이터베이스 연결 실패
- 타임아웃
- 인증 오류

처리 방식:
- 상태: ERROR
- 메시지: "데이터베이스 연결 오류가 발생했습니다."
- SQL 실행 중단
- SLM 설명 문장 생성 금지
- **오류 상세 내용은 서버 로그로 기록한다**

---

### 6.2 SQL 실행 오류

- SQL 문법 오류
- 실행 중 예외 발생

처리 방식:
- 상태: ERROR
- 메시지: "데이터베이스 연결 오류가 발생했습니다."
- SQL 실행 중단
- SLM 설명 문장 생성 금지
- **오류 상세 내용은 서버 로그로 기록한다**


---

### 6.3 조회 결과 없음 (데이터 없음)

- SQL 실행 성공
- 결과 row 수 = 0

처리 방식:
- 상태: OK
- 메시지: "조회된 데이터가 없습니다."
- result는 빈 구조로 반환
- 오류로 처리하지 않는다
- **해당 상황은 정보성 로그(INFO)로 기록할 수 있다**

---

### 6.4 존재하지 않는 설비 또는 현장

- sitename 또는 facilitytype이 DB에 존재하지 않음

처리 방식:
- 상태: ERROR
- 메시지: "존재하지 않는 설비 또는 현장입니다."
- 추천 질문(recquestions) 포함 가능

---

### 6.5 JSONB 스키마 불일치

- DB JSONB 구조가 `db_jsonb_schema.md`와 다를 경우

처리 방식:
- 상태: ERROR
- 메시지: "데이터 구조 오류가 발생했습니다."
- 즉시 실패 처리
- 조용히 무시하거나 기본값으로 대체하지 않는다
- **위반된 JSONB key 및 경로는 서버 로그로 기록한다**

---

## 7. 응답 생성 원칙

- API 응답 구조는 example3.json의  
  answer_template, meta, chart_type 정의를 따른다.
- ai_server.py는 해당 구조를 조립·보정만 수행한다.
- UI가 판단 로직을 가지지 않도록,  
  응답은 해석이 필요 없는 형태로 제공한다.

---

## 8. 최종 원칙 요약

- 이 서버는 판단 시스템이 아니다.
- 실행 실패와 질의 실패는 명확히 구분한다.
- 데이터 오류는 숨기지 않고 즉시 드러낸다.
- 정책(example3.json)과 실행(ai_server.py)은 분리한다.
