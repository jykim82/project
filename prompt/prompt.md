당신은 반드시 이 문서들을 계약(contract)으로 간주하고 코드를 작성해야 합니다.

[JSONB 처리에 대한 절대 규칙]

- DB의 JSONB 컬럼은 SQL에서 가공하지 않습니다.
- SQL은 JSONB 컬럼을 그대로 조회합니다.
- JSONB 구조 해석은 Python에서만 수행합니다.
- JSONB 접근은 반드시 전용 파서 함수에서만 수행합니다.

다음 행위는 절대 금지됩니다:
- dict.get().get() 체인 사용
- KeyError를 무시하는 try/except
- 기본값을 사용하여 구조 오류를 숨기는 코드
- SQL에서 jsonb ->, ->> 남용

JSONB 구조는 다음 문서를 신뢰합니다:
- docs/db_jsonb_schema.md

Python 구현 규칙은 다음 문서를 신뢰합니다:
- docs/python_jsonb_implementation_guide.md

[INTENT 및 정책 관련 규칙]

- INTENT 정의, 질문 문구, SQL 구조는 example3.json 및
  docs/example3_policy.md를 그대로 따릅니다.
- 질문 문구 단위로 로직을 분기하지 않습니다.
- 반드시 INTENT(의미 단위) 기준으로 구현합니다.

---

[SLM 관련 규칙]

- SLM은 판단자가 아닙니다.
- SLM은 이미 결정된 결과를 설명하는 역할만 수행합니다.
- "정상", "이상"과 같은 단정적 판단 문구를 생성하지 마십시오.
- 설명 문장은 answer_template 및 Python 후처리 결과를 기반으로 생성합니다.

---

[에러 처리 원칙]

- JSONB 구조가 문서와 다를 경우 즉시 실패해야 합니다.
- 조용히 넘어가는 코드는 작성하지 마십시오.
- 필요 시 명시적 예외 클래스(JsonbSchemaViolation 등)를 사용하십시오.
